# GitHub labels

Create these labels in **Issues → Labels → New label**. Colors are suggested; name and meaning are the important parts.

| Label | Suggested color | Meaning |
|---|---|---|
| `team:ai` | `#5319e7` | AI & NLP (M1) |
| `team:mobile` | `#1d76db` | Mobile app (M4/M5) |
| `team:backend` | `#0052cc` | Backend & database (M3) |
| `team:data` | `#008672` | Data and intelligent inputs (M2/M6) |
| `team:qa` | `#d876e3` | QA, integration, project coordination (M7) |
| `priority:high` | `#b60205` | Blocks milestone, safety, or core MVP |
| `priority:medium` | `#fbca04` | Important, planned for current/next iteration |
| `priority:low` | `#c5def5` | Useful but not currently blocking |
| `type:feature` | `#a2eeef` | New product or engineering capability |
| `type:bug` | `#d73a4a` | Incorrect behavior to fix |
| `type:research` | `#d4c5f9` | Investigation or evaluation with a written result |
| `type:documentation` | `#0075ca` | Documentation or process work |
| `type:testing` | `#bfd4f2` | Test plan, test implementation, or evaluation |

Apply at least one team, one priority, and one type label to each issue. Avoid assigning a person until their GitHub username is known.
