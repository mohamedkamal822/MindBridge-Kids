# Safety requirements

**Owner:** M7 coordinates review with all module owners and specialist input where available.

Document non-diagnostic/non-therapeutic boundaries, age-appropriate language, uncertainty/fallback behavior, sensitive-disclosure escalation, privacy flows, and review evidence. A qualified child mental-health professional and communication/ESL specialist should advise on content and safety. Obtain applicable institutional ethics review, guardian consent, and child-appropriate assent before research involving children; never promise absolute confidentiality. Specialist-approved adult-support wording must be reachable from every child screen.

Do not infer psychological states from faces, voice tone, sign use, retries, engagement, or task completion. Do not present emotional-awareness activities as treatment or claim mental-health benefit from usage metrics. Use synthetic/adversarial cases and specialist review before any child-facing pilot. Review external LLM/speech vendor terms and data flows before sending any child input; do not send identifiable information without explicit approval and legal/institutional basis.

Mobile controls to verify: on-demand camera/microphone permissions; parent gate for caregiver/settings/external links/deletion; no ads, purchases, child push notifications, or behavioral analytics in child mode; third-party SDK inventory; redacted logs/screenshots; token storage in OS secure storage; clear local data on sign-out; documented retention/deletion; and role-based/audited caregiver and specialist access. Re-check current store family/children policies before distribution. This file records project requirements, not legal advice or evidence that controls are implemented.
